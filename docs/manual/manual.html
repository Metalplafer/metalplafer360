La regla de oro sobre las contraseñas

En este manual vas a manejar algunas claves. Hay una que no se pega nunca en GitHub ni en ningún archivo del programa: la que Supabase llama service_role. Lo mismo vale para el archivo de credenciales de Google. Esas dos cosas solo se pegan dentro de Supabase, que es un sitio privado. Si dudas: si parece una contraseña o una clave larguísima, no va a GitHub.

1Crear la cuenta de Supabase

Supabase es el servicio donde vivirán los datos de la empresa: los clientes, los presupuestos, las horas, las fotografías. Es gratis para un taller de este tamaño.

  1. Entra en supabase.com y pulsa Start your project.
  2. Regístrate con la cuenta de Google de la empresa o con un correo y una contraseña.
  3. Si te pide confirmar el correo, abre el mensaje que te envían y pulsa el enlace.

Apunta en un sitio seguro con qué correo te has registrado. Es la llave de todo lo demás.

2Crear el proyecto

  1. Pulsa New project.
  2. En Name escribe metalplafer360.
  3. En Database Password pulsa Generate a password y cópiala a un sitio seguro. No la vas a necesitar para el día a día, pero si la pierdes no se puede recuperar.
  4. En Region elige West EU (Ireland) o Central EU (Frankfurt): son las más cercanas y la aplicación irá más rápida.
  5. Pulsa Create new project y espera un par de minutos.
Los proyectos gratuitos se duermen

Si nadie entra durante una semana, Supabase pausa el proyecto y la aplicación dejará de conectar. Se despierta entrando en supabase.com y pulsando Restore project. Usándola a diario no pasa nunca.

  2. Pulsa New query.
  3. Abre en GitHub el archivo supabase/sql/01_schema.sql, pulsa el botón de copiar (el icono de dos hojas, arriba a la derecha) y pégalo en la ventana de Supabase.
  4. Pulsa Run (abajo a la derecha). Debe aparecer Success. No rows returned.
  5. Borra la ventana y repite con cada archivo de la lista, en este orden exacto.

Comprobar que ha ido bien

Pega esto en una ventana nueva y pulsa Run. Las cuatro filas deben decir CORRECTO:

select 'Tablas creadas' as comprobacion,
       case when count(*) = 18 then 'CORRECTO' else 'FALTAN TABLAS' end as resultado
  from pg_tables where schemaname = 'public'
   and tablename in ('profiles','app_settings','code_counters','audit_log',
                     'clients','client_contacts','fichas','documents','comments',
                     'projects','project_substatuses','work_orders',
                     'work_order_workers','notifications','materials',
                     'material_requests','payments','backups')
union all
select 'Seguridad activada',
       case when bool_and(rowsecurity) then 'CORRECTO' else 'HAY TABLAS SIN PROTEGER' end
  from pg_tables where schemaname = 'public'
union all
select 'Almacén de archivos',
       case when exists (select 1 from storage.buckets
                          where id = 'documentos' and not public)
            then 'CORRECTO' else 'FALTA' end
union all
select 'Panel, informes y copias',
       case when count(*) = 11 then 'CORRECTO' else 'FALTAN FUNCIONES' end
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public'
   and p.proname in ('dashboard_summary','report_projects','report_projects_by_phase',
                     'report_hours_by_worker','report_hours_by_project','report_materials',
                     'report_suppliers','start_backup','finish_backup','restore_data',
                     'restore_table');

4Las tablas: qué se guarda y dónde

No hace falta que toques nada de esto, pero conviene saber qué hay dentro por si algún día quieres mirar un dato directamente en Supabase (Table Editor en el menú de la izquierda).

TablaQué guarda
profilesQuién es cada persona y si es administración o trabajador
clients · client_contactsClientes y sus personas de contacto
fichasPresupuestos, visitas y avisos, con su código anual

Aquí no se borra nada

Los clientes, fichas, proyectos, órdenes y materiales se archivan: desaparecen del listado pero conservan su historial. Los documentos van a una papelera de la que se pueden recuperar. Un cobro apuntado por error se anula y se queda tachado a la vista. Y a las personas no se les borra: se les desactiva.

5Los permisos: por qué esto es seguro

Esta es la parte más importante del manual, aunque no tengas que hacer nada.

La seguridad de METALPLAFER360 no está en la pantalla. No se trata de esconderle botones al trabajador: eso sería fácil de saltarse. Está en la propia base de datos, con una tecnología que se llama seguridad a nivel de fila (RLS, por sus siglas en inglés).

Cada vez que la aplicación pide un dato, PostgreSQL comprueba quién lo pide y solo le devuelve lo que le corresponde. Da igual que alguien manipule la aplicación desde el navegador, que escriba una dirección a mano o que use herramientas de programador: el candado está en el servidor, no en el botón.

QuiénQué ve
AdministraciónTodo
Trabajador Solo sus órdenes, los proyectos y clientes de esas órdenes, sus propias horas, sus avisos y su historial
Trabajador Nunca: informes, configuración, facturación, cobros, copias de seguridad, numeración ni los datos de otros compañeros

Esto está comprobado con más de 500 pruebas automáticas que se ejecutan contra una base de datos de verdad, incluidas las que intentan saltarse los permisos a mala fe.

6El acceso de las personas

En METALPLAFER360 cada persona entra con un nombre de usuario y una contraseña. No hace falta que nadie tenga correo electrónico de empresa.

Por dentro, Supabase necesita una dirección de correo para identificar a cada persona, así que la aplicación le añade sola un dominio interno: si el usuario es juan, por dentro se guarda como juan@metalplafer.com. No se envía ningún correo electrónico nunca: es solo un identificador.

Desactivar los registros públicos

Para que nadie pueda darse de alta por su cuenta:

  1. En Supabase, menú de la izquierda → Authentication.
  2. Pestaña Sign In / Providers (o Providers).
  3. Busca Allow new users to sign up y desactívalo.
  4. Guarda.

Hazlo después de crear el primer administrador (apartado 8), no antes, o no podrás crearlo.

7El almacén de archivos

Las fotografías de obra, los planos, los vídeos y las firmas no se guardan en la base de datos: van a un almacén aparte que el archivo 04_storage.sql ya creó, y que se llama documentos.

Ese almacén es privado. Nadie puede abrir una fotografía con solo conocer su dirección: la aplicación pide un enlace temporal cada vez, y ese enlace caduca. Y un trabajador solo obtiene enlaces de los archivos de sus propias órdenes.

El tamaño máximo por archivo

De serie son 100 MB, que da de sobra para fotos y vídeos de móvil. Se cambia desde la propia aplicación, en Configuración → Almacenamiento, y el límite lo aplica la base de datos, no solo la pantalla.

En Configuración → Almacenamiento también ves cuánto ocupan las fotografías, los vídeos, las firmas y los documentos, y cuánto hay esperando en la papelera.

8Crear el primer administrador

La primera persona que se da de alta se convierte automáticamente en administración. Las siguientes nacen como trabajadores. Esto es a propósito: así nadie puede concederse permisos por su cuenta.

  1. En Supabase: Authentication → Users → Add user → Create new user.
  2. En Email escribe salvi@metalplafer.com (el nombre de usuario que quieras, seguido de @metalplafer.com).
  3. En Password pon una contraseña de al menos 8 caracteres y apúntala.
  4. Marca Auto Confirm User.
  5. Pulsa Create user.

Para comprobar que ha nacido como administración, ejecuta en el SQL Editor:

select full_name as nombre, username as usuario, role as rol, active as activo
  from public.profiles;

Debe salir una fila con rol = admin.

Si por lo que sea saliera worker, se arregla con:
update public.profiles set role = 'admin' where username = 'salvi';

9Las claves de conexión

La aplicación necesita saber dónde está su base de datos. Son dos datos que se copian de Supabase a GitHub.

Cogerlos en Supabase

  1. Project Settings (la rueda dentada, abajo a la izquierda).
  2. Apartado Data API: copia Project URL. Es algo como https://abcdefgh.supabase.co.
  3. Apartado API Keys: copia la clave anon (también llamada public). Es un texto larguísimo.
La clave «anon» sí puede ir a GitHub

Parece una contraseña, pero no lo es: solo sirve para decir «soy la aplicación de Metalplafer». Quien la tenga no puede ver ni un dato, porque los permisos los aplica la base de datos según quién haya iniciado sesión. Está diseñada para viajar al navegador.

La clave «service_role» NO va a GitHub. Nunca.

En esa misma pantalla verás otra clave llamada service_role o secret. Esa se salta todos los permisos. No se pega en GitHub, ni en el programa, ni en un correo, ni en un WhatsApp. Solo se usa dentro de Supabase, y de eso se encarga el apartado 10.

Pegarlos en GitHub

  1. Entra en el repositorio en GitHub.
  2. Settings → Secrets and variables → Actions → pestaña Variables.
  3. Pulsa New repository variable y crea estas tres:
NombreValor
VITE_SUPABASE_URLLa Project URL que copiaste
VITE_SUPABASE_ANON_KEYLa clave anon
VITE_LOGIN_DOMAINmetalplafer.com

Fíjate en que sea la pestaña Variables y no Secrets. Si las pones en Secrets, la aplicación se publicará sin conexión y en la pantalla de acceso dirá que no está configurada.

10Google Drive (opcional)

Esto se puede dejar para otro día. Sin hacer nada de este apartado, la aplicación ya hace copias de seguridad: en Configuración → Copias de seguridad tienes el botón GENERAR BACKUP AHORA, que descarga un ZIP a tu ordenador.

Lo que se configura aquí es que esa copia se haga sola, todas las noches, y se guarde en Google Drive, fuera de Supabase.

10.1 · Crear la cuenta de servicio en Google

Una «cuenta de servicio» es un usuario de Google que no es una persona: es el programa que sube las copias.

  1. Entra en console.cloud.google.com con la cuenta de la empresa.
  2. Arriba a la izquierda, New project. Llámalo metalplafer360 y créalo.
  3. En el buscador de arriba escribe Google Drive API, ábrela y pulsa Enable.
  4. En el buscador escribe Service accounts y ábrelo.
  5. Create service account → nombre copias-metalplafer360 → Create and continue → Done.
  6. Copia su dirección de correo, que acaba en .iam.gserviceaccount.com. La necesitarás dos veces.
  7. Pulsa sobre ella → pestaña Keys → Add key → Create new key → formato JSON → Create.

Se te descarga un archivo .json. Ese archivo es la llave de la caja fuerte. No lo subas a ningún sitio y bórralo de tu ordenador en cuanto termines este apartado.

10.2 · Crear la carpeta en Drive y compartirla

  1. En drive.google.com, crea una carpeta llamada METALPLAFER360 · Copias de seguridad.
  2. Ábrela, pulsa Compartir, pega la dirección de la cuenta de servicio, dale permiso de Editor y envía.
  3. Con la carpeta abierta, mira la dirección del navegador: al final hay un código largo después de /folders/. Cópialo.

10.3 · Guardar los secretos en Supabase

En Supabase: Edge Functions → pestaña Secrets (en algunas versiones, Project Settings → Edge Functions → Secrets). Añade estos cuatro:

NombreValor
GOOGLE_SERVICE_ACCOUNT_EMAILLa dirección de la cuenta de servicio
GOOGLE_PRIVATE_KEYEl valor de private_key del archivo JSON
GOOGLE_DRIVE_FOLDER_IDEl código de la carpeta
BACKUP_CRON_SECRETUna frase larga que te inventes

Para sacar GOOGLE_PRIVATE_KEY: abre el archivo .json con el Bloc de notas, busca la línea que empieza por "private_key": y copia todo lo que hay entre comillas, desde -----BEGIN PRIVATE KEY----- hasta el final. Se copia tal cual, con los \n incluidos.

10.4 · Publicar los dos programas del servidor

Esto se hace una sola vez, desde la Terminal, en la carpeta del proyecto:

npm install -g supabase
supabase login
supabase link --project-ref TU-REFERENCIA-DE-PROYECTO
supabase functions deploy admin-users
supabase functions deploy backup-drive

La referencia del proyecto es el trozo de la dirección de Supabase entre https:// y .supabase.co.

Si prefieres no instalar nada, la aplicación funciona igual. Solo dejan de estar disponibles el botón «Subir a Google Drive», la copia automática y el alta de trabajadores desde la aplicación (se pueden seguir creando a mano, apartado 16).

11Las copias de seguridad

A mano, cuando quieras

Configuración → Copias de seguridad → GENERAR BACKUP AHORA. Se descarga un ZIP a tu ordenador con todo lo que hay dentro de la aplicación.

Dentro del ZIP encontrarás:

  • Un archivo CSV por cada tabla, que se abre con Excel.
  • Un metadatos.json con lo necesario para restaurar.
  • Un índice con la referencia de cada foto, vídeo y documento.

Las fotografías y los vídeos no se convierten en CSV. Siguen guardados en el almacén de Supabase; en el ZIP va su ruta y sus datos. Es a propósito: meterlos dentro haría la copia enorme y lentísima.

Automática, todas las noches

Solo si has hecho el apartado 10. En el SQL Editor de Supabase, una vez:

select vault.create_secret('https://TU-REFERENCIA.supabase.co', 'm360_project_url');
select vault.create_secret('la-misma-frase-de-BACKUP_CRON_SECRET', 'm360_backup_secret');

Y después ejecuta el archivo supabase/sql/21_backup_automatico.sql. Debe aparecer un aviso que dice «Copia automática programada: todos los días a las 02:00 (hora de Madrid)».

Se guardan 30 días de copias, y se puede cambiar en Configuración → Copias de seguridad. Las automáticas más antiguas se borran solas de Drive; las que te descargues tú no se tocan.

Comprobar que se sigue haciendo

De vez en cuando, ejecuta en el SQL Editor:

select case when max(started_at) is null
            then 'NUNCA se ha hecho una copia automática'
            when max(started_at) > now() - interval '36 hours'
            then 'CORRECTO: al día'
            else 'ATENCIÓN: la última fue el '
                 || to_char(max(started_at) at time zone 'Europe/Madrid', 'DD/MM/YYYY')
       end as copia_automatica
  from public.backups
 where kind = 'automatico' and status = 'completado';

12Restaurar una copia

Solo hace falta si se ha perdido o estropeado información.

⚠️ Esta operación puede modificar información actual

Los datos de la copia se vuelcan sobre los de ahora: lo que coincide se actualiza y lo que falta se añade. No se borra nada, pero lo que se sobrescriba no vuelve. Genera una copia antes, por si acaso.

  1. Configuración → Copias de seguridad.
  2. Antes de nada, pulsa GENERAR BACKUP AHORA para tener el estado actual.
  3. Baja hasta Restaurar una copia y pulsa Elegir archivo de copia.
  4. La aplicación te dice de cuándo es la copia y cuántos registros trae.
  5. Marca qué apartados quieres restaurar: puedes traerte solo los clientes, solo los proyectos, o todo.
  6. Pulsa Restaurar lo marcado y confirma.

Restaurar no crea usuarios nuevos. Si en la copia aparece una persona que ya no existe, sus datos no se recrean: hay que darla de alta otra vez (apartado 16). Es a propósito, porque el acceso vive en Supabase, no en la copia.

Toda restauración queda registrada en el historial, con quién la hizo y qué apartados tocó, y la numeración de códigos se reajusta sola para que el siguiente presupuesto no repita un número.

14Publicar la aplicación

  1. En GitHub: Settings → Pages.
  2. En Source elige GitHub Actions.
  3. Ve a la pestaña Actions → Publicar METALPLAFER360 → Run workflow.
  4. Espera dos o tres minutos a que salga la marca verde.

La dirección de la aplicación será algo como https://TU-USUARIO.github.io/metalplafer360/. Esa es la que se reparte a la gente del taller.

A partir de ahora, cada vez que se suba un cambio a GitHub la aplicación se reconstruye y se publica sola. No hay que hacer nada más.

15Entrar por primera vez

  1. Abre la dirección de la aplicación.
  2. Escribe el usuario (salvi, sin el @metalplafer.com) y la contraseña.
  3. Pulsa Entrar.

Los primeros diez minutos

  1. Ve a Configuración → Empresa y rellena el nombre, el CIF, el teléfono y la dirección. Eso es lo que sale en los informes en PDF.
  2. En Configuración → Aplicación, pulsa Poner datos de ejemplo y date una vuelta por la aplicación con datos dentro (apartado 17).
  3. Cuando te hayas hecho a ella, pulsa Limpiar datos demo.
  4. Da de alta a la gente del taller (apartado 16).
  5. Instala la aplicación en el móvil: en Android, menú del navegador → «Añadir a pantalla de inicio»; en iPhone, botón Compartir → «Añadir a pantalla de inicio».

La aplicación necesita Internet, y es a propósito: en una obra es peor trabajar con datos viejos que no poder entrar. Instalada en el móvil solo se guardan las pantallas y los iconos, nunca los datos de la empresa.

16Dar de alta trabajadores

Desde la aplicación (si hiciste el apartado 10.4)

  1. Trabajadores → Nuevo trabajador.
  2. Escribe el nombre, el usuario (juan) y una contraseña.
  3. La persona ya puede entrar. Nace como trabajador; para darle permisos de administración, usa el selector de su fila.

A mano, desde Supabase

  1. Authentication → Users → Add user.
  2. Email: juan@metalplafer.com. Contraseña: la que sea.
  3. Marca Auto Confirm User y crea.
  4. Entra en la aplicación, ve a Trabajadores y corrige su nombre completo.
A nadie se le borra

Cuando alguien deja la empresa, se le desactiva desde Trabajadores. Deja de poder entrar, pero sus horas y su historial siguen ahí. Si intentas borrarlo desde Supabase, la base de datos se negará: es una protección puesta a propósito para que no se pierdan horas ya trabajadas y facturadas.

17Los datos de ejemplo

Para aprender a usar la aplicación, enseñarla o hacer pruebas sin miedo, hay un taller inventado listo para poner.

  1. Ejecuta una vez en el SQL Editor el archivo supabase/sql/23_datos_demo.sql.
  2. En la aplicación: Configuración → Aplicación → Poner datos de ejemplo.

Se crean 10 clientes, 15 fichas, 8 proyectos, 6 trabajadores, 20 órdenes de trabajo, material, documentos y cobros, con fechas recientes.

Limpiarlo es completamente seguro

El botón Limpiar datos demo borra exactamente lo que se creó como ejemplo y nada más. Cada fila lleva una marca por dentro, y la limpieza solo mira esa marca. Lo que haya hecho la empresa de verdad no se toca, aunque esté mezclado.

Los trabajadores de ejemplo se llaman demo.jordi, demo.marc… y nacen sin contraseña; si quieres entrar como uno para ver el móvil, pónsela desde Trabajadores. Los documentos de ejemplo son solo la ficha del archivo: aparecen en los listados, pero no hay nada que descargar.

18Actualizaciones

Cuando llegue una versión nueva del programa:

  1. Sube los archivos nuevos a GitHub (o acepta el cambio que te propongan).
  2. La aplicación se reconstruye y se publica sola en un par de minutos.
  3. Si la versión trae archivos SQL nuevos, ejecútalos en Supabase en orden, como en el apartado 3. Los que ya ejecutaste no hay que repetirlos.
  4. En el móvil, la aplicación avisa sola de que hay una versión nueva y se actualiza al recargar.

Los archivos SQL están pensados para poder ejecutarse más de una vez sin romper nada. Si dudas si ya ejecutaste uno, ejecutarlo otra vez es seguro.

19Si algo no funciona

Qué vesQué hacer
«La aplicación todavía no está configurada» Las variables de GitHub están vacías o mal escritas. Revisa el apartado 9: deben estar en Variables, no en Secrets. Después, Actions → Run workflow otra vez.
«Usuario o contraseña incorrectos» Revisa en Authentication → Users. Puedes cambiar la contraseña con ⋯ → Reset password.
«Tu usuario no tiene perfil» Se creó antes de ejecutar el SQL. Bórralo en Authentication → Users y créalo otra vez.
«Tu usuario está desactivado» Reactívalo desde Trabajadores, o con update public.profiles set active = true where username = 'juan';
«No se ha podido conectar con el servidor» Sin Internet, o el proyecto de Supabase está pausado: entra en supabase.com y pulsa Restore project.
El trabajador no ve ninguna orden No se le ha asignado ninguna, o son de días futuros. Las futuras se ven, pero no se rellenan hasta su fecha.
«Falta configurar Google Drive» No están puestos los secretos de Google. Repasa el apartado 10.3. El botón GENERAR BACKUP AHORA funciona igual sin eso.
«Google no ha dado acceso» La clave privada está mal copiada, o la carpeta de Drive no está compartida con la cuenta de servicio. Repasa 10.2 y 10.3.
La copia automática no se hace No se ejecutó el archivo 21, o faltan los secretos de la bóveda. Repasa el apartado 11.
El Excel se ve todo en una columna Excel está en inglés. Ábrelo con Datos → Desde texto/CSV y elige el punto y coma como separador. Los informes en .xlsx no tienen este problema.
No se puede borrar algo Es correcto: aquí no se borra nada. Los clientes, proyectos, órdenes y materiales se archivan; los documentos van a la papelera; los cobros se anulan; a las personas se les desactiva.
Un código de presupuesto o proyecto está mal Los códigos no se pueden cambiar a propósito: identifican el expediente en presupuestos y facturas de papel. Si hay que corregir la numeración de las próximas fichas, se hace en Configuración → Numeración.

Consultas de apoyo

El archivo supabase/sql/05_verificacion.sql tiene casi treinta consultas preparadas y explicadas: ver quién puede entrar, cambiar un rol, mirar el historial, las órdenes abiertas, el material retrasado, la facturación pendiente o el estado de las copias de seguridad.
